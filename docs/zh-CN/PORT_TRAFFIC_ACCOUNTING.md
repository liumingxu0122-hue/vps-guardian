# 端口流量统计

## 范围

VPS Guardian 使用内核字节计数器统计明确的 TCP/UDP 单端口或有限端口段。RX、TX
分别保存，合计始终是 `RX + TX`，不使用权重。首版支持监控、可选配额执行和可选
出站 TC 限速；入站限速和 IFB 留待后续版本。

每条策略必须从 `monitor_only` 开始。策略绑定单台主机、协议、方向、端口、可选
接口、可选字节配额、重置周期和可选出站速率。活动策略的协议/端口范围不得重叠，
每台主机最多 64 条。

## 数据模型与保留

PostgreSQL migration `0013_port_traffic` 新增策略、原始样本、小时聚合、日聚合、
重置事件和运行状态表。原始数据保留 7 天，小时聚合 90 天，日聚合 400 天；
历史查询最多 400 天、10,000 点。

helper 保存累计计数。只有 generation 不变且 RX/TX 均单调递增时，Controller
才计算差值。generation 变化、计数下降、规则缺失或心跳缺口都会明确记录为不连续。
首个样本只作为基线，不会作为“0 流量”区间返回。

每条批量策略观测都包含准确的 RX、TX、累计/当前周期合计、配额值/百分比/状态、
重置策略与边界、generation、运行/限速状态、可可靠取得的出站速率、采集时间和
不连续原因。Controller 会根据原始计数重新计算统计和配额判断，不会把 Agent 派生
合计直接用于计费或执行决策。

时间统一以 UTC 入库。重置周期携带 IANA 时区，月末日期会安全收敛。Web 按用户
本地时区（包括 DST）显示，小时/日存储桶仍保持 UTC。非手工计划只有通过独立
批准的计划变更申请后才生效；直接创建或更新都会失败关闭。

## 告警

配额沿用现有持久化告警状态机，阈值为 70%、85%、95%、100%，恢复使用 2 个
百分点迟滞，并沿用现有去重与恢复通知。规则缺失和采样缺口保持为运行状态降级，
不会伪造成用量。

## 当前状态

0/1/10/64 策略资源预算及双 VPS Staging 仍是门禁；Production 为 **NO-GO**。
